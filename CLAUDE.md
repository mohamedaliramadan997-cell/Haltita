# Project instructions: حالتيتا (Haltita)

Before any task, read in this order: `docs/rules.md`, `docs/memory.md`, then `docs/tasks.md`.
Consult `docs/prd.md` for scope and game rules, `docs/architecture.md` for structure, data, security, cloud and CI/CD, and `docs/design.md` for any UI work.

- Work on ONE task from `docs/tasks.md` at a time, on its own branch `t/T-0xx-slug`.
- When done: run typecheck, lint and tests; tick the task; append a session entry to `docs/memory.md`.
- Do not change the tech stack, folder structure, game rules or design tokens without asking. If a change is agreed, update the owning doc and log an ADR in `docs/memory.md`.
- Fixes: give exact find-and-replace instructions, not full-file rewrites.
